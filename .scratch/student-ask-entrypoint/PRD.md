# PRD: 学生提问页入口即提问体验修正

## Problem Statement

学生端已经围绕“学习提问 / 篇目项目 / 层级挑战 / 我的画像”建立了角色化导航，也需要一个总的 dashboard 来呈现项目学习状态、认知分布和下一步行动。但是“学习提问”本身不是看板入口。学生点击“学习提问”时，心智不是先看指标、卡片或总览，而是马上把“这首诗我哪里没懂”问出来。

当前风险是把总 dashboard、项目概览、Bloom 分布、挑战推荐等内容塞进提问页首屏，导致学生进入核心功能前先被看板打断。这样会削弱学生端最核心的黄金路径：自然提问 → 自动归属篇目项目 → 看到轻量归属反馈 → 获得 AI 回答 → 感知 Bloom 认知变化 → 进入挑战确认认知水平。

## Solution

保留学生总 dashboard，但把它定义为独立的“学习总览 / 学生看板”表面；“学习提问”页面必须入口即提问。学生进入提问页后，首屏应直接呈现可输入问题的学习工作区：左侧项目与会话上下文，中间对话区域，右侧或顶部展示轻量 Bloom / 项目归属状态。所有总览型内容只能作为辅助信息或独立页面存在，不能占据提问页首屏、不能挡在输入框之前、不能让学生先选择一堆卡片才可以提问。

这不是视觉微调，而是学生端信息架构边界：dashboard 负责“我最近学得怎么样、哪些篇目有进展、下一步可以做什么”；提问页负责“我现在就要问 AI 一个古诗文学习问题”。挑战继续保持独立入口，因为挑战用于确认认知水平，不应混入普通提问对话。

## User Stories

1. As a 学生, I want 点击“学习提问”后马上看到输入框, so that 我可以立即提出古诗文学习问题。
2. As a 学生, I want 提问页首屏就是对话工作区, so that 我不会先被指标、卡片或看板信息打断。
3. As a 学生, I want 在提问页不用先选择 dashboard 卡片, so that 我可以像自然问老师一样直接开始。
4. As a 学生, I want 输入框在首屏稳定可见, so that 我不需要滚动页面才能开始提问。
5. As a 学生, I want 对话主区占据提问页视觉中心, so that 我明确知道当前页面的主要任务是提问。
6. As a 学生, I want 左侧看到篇目项目和会话上下文, so that 我知道当前问题会沉淀到哪个学习项目。
7. As a 学生, I want 系统自动把问题归属到篇目项目, so that 我不用先手动创建或选择项目才能提问。
8. As a 学生, I want 项目归属反馈轻量出现在回答区, so that 我知道问题已归入《篇目》但对话不中断。
9. As a 学生, I want 项目侧栏高亮对应篇目, so that 我能感知提问已经进入项目层级。
10. As a 学生, I want 项目归属不触发强制跳转, so that 我可以继续追问当前问题。
11. As a 学生, I want 在提问过程中看到轻量 Bloom 层级提示, so that 我知道自己的问题处在理解、分析或评价等认知层级。
12. As a 学生, I want Bloom 信息不压过对话输入, so that 认知反馈帮助我学习而不是阻碍我提问。
13. As a 学生, I want AI 回答后看到“你可以尝试……”的攀升提示, so that 我知道下一步如何提出更高层次的问题。
14. As a 学生, I want 可以复制或继续追问 AI 回答, so that 我能围绕同一篇目持续学习。
15. As a 学生, I want 教师修订过的回答显示修订提示, so that 我知道这条内容已经被教师核实过。
16. As a 学生, I want 提问页不要展示大型总览指标, so that 我不会把当前任务误解为查看学习报告。
17. As a 学生, I want 提问页不要用“今日任务看板”遮挡输入, so that 我可以按自己的疑问自然开始。
18. As a 学生, I want 学习总览保留项目进度和认知分布, so that 我需要复盘时仍能看到整体学习状态。
19. As a 学生, I want 学习总览提供“继续提问”入口, so that 我可以从 dashboard 快速回到提问工作区。
20. As a 学生, I want 学习总览提供“进入挑战”入口, so that 我可以在准备好后确认自己的认知水平。
21. As a 学生, I want 学习总览和学习提问职责分明, so that 我不会在学习过程中迷失当前页面目的。
22. As a 学生, I want 挑战入口保持独立, so that 我能区分普通求助和正式认知确认。
23. As a 学生, I want 在项目详情中查看历史会话和认知路径, so that 我可以复盘某个篇目的学习过程。
24. As a 学生, I want 提问页支持空状态直接引导我输入问题, so that 第一次使用时也能马上开始。
25. As a 学生, I want 提问页加载中仍保留输入区域骨架, so that 我知道页面即将进入提问状态。
26. As a 学生, I want 提问失败时保留我的问题草稿, so that 我可以重试而不丢失思路。
27. As a 学生, I want 移动端进入提问页也优先看到输入和对话, so that 小屏设备上仍然入口即提问。
28. As a 学生, I want 移动端的项目/Bloom 信息可以折叠, so that 辅助信息不占走提问空间。
29. As a 教师, I want 学生的提问路径保持自然, so that 学生更愿意暴露真实不懂的问题。
30. As a 教师, I want 学生问题自动沉淀到项目, so that 后续学习记录核实时能按篇目理解上下文。
31. As a 教师, I want 学生先提问而不是先看报告, so that 学习过程数据来自真实困惑而不是被看板诱导。
32. As an 管理员, I want 学生端信息架构清晰区分总览、提问、项目和挑战, so that 后续运营和权限配置不会混乱。
33. As a 开发者, I want 学生提问页有明确验收规则“首屏可输入”, so that 实现时不会再次把 Hero 或 dashboard 放在输入框前面。
34. As a 开发者, I want dashboard 与 ask workspace 的模块边界明确, so that 组件复用不会导致看板内容泄漏到提问页首屏。
35. As a 开发者, I want 测试覆盖提问页首屏关键行为, so that 未来 UI 重构不会回归成看板式入口。
36. As a 设计者, I want 提问页的视觉重心落在输入和对话, so that 页面布局服务学生核心任务。
37. As a 设计者, I want dashboard 的卡片、指标、认知分布留在总览页, so that 信息密度出现在正确场景。
38. As a 产品负责人, I want “学习提问”命名和页面行为一致, so that 用户点击入口后的预期不会落空。
39. As a 产品负责人, I want 总 dashboard 存在但不替代提问页, so that 产品既有整体学习管理，也不牺牲即时提问效率。
40. As a 产品负责人, I want 这条规则写进 PRD 和验收标准, so that 后续实现不能用“看板也很重要”来稀释提问入口。

## Implementation Decisions

- 学生端保留一个总 dashboard，用于学习状态总览、项目进度、Bloom 认知分布、下一步行动和继续学习入口。
- “学习提问”必须是独立 ask workspace，进入后首屏直接显示对话区域和可用输入框。
- Dashboard 与 ask workspace 是同级信息架构表面，不允许把 dashboard 作为学习提问页的前置步骤。
- 提问页可以包含项目上下文、会话列表、轻量 Bloom 状态和攀升提示，但这些都必须服务当前对话，不能替代输入区。
- 项目归属继续自动发生：学生自然提问后，系统判断篇目项目并给出轻量反馈。
- 项目归属反馈应在对话流或侧栏中呈现，不强制跳转、不弹出阻塞确认、不要求学生先配置项目。
- 挑战保持独立入口；提问页可以提示“进入挑战”，但不能把挑战题目混入普通对话主流程。
- 学生总 dashboard 可以提供“继续提问”“继续挑战”“查看项目”等动作，但这些动作必须把学生带到对应工作区。
- 移动端需要保持同样原则：首屏优先输入与对话，项目/Bloom/dashboard 类信息折叠或下沉。
- 空状态必须围绕“提出第一个问题”设计，而不是围绕“查看看板数据”设计。
- 加载、错误、无项目、无历史会话等状态都不能遮挡或取消提问入口。
- 可复用模块应按职责拆分为学习总览、提问工作区、项目/会话上下文、Bloom 状态反馈、挑战入口提示，避免浅层组件把看板布局耦合进提问页。
- 深模块优先方向：提问工作区状态模型应封装输入草稿、会话流、项目归属反馈、Bloom 反馈和错误重试，对外提供稳定的“学生正在提问”界面。
- 不改变教师端“学习记录核实”语境，不把学生侧 Bloom/挑战反馈扩散成教师侧训练数据术语。
- 不改变管理员 AI Native 后台术语边界。

## Testing Decisions

- 好测试应验证学生看到和能做什么，而不是验证组件内部怎么拆。核心断言是：进入“学习提问”后，首屏存在可用输入框和对话工作区。
- 学习提问页测试应覆盖：首次访问空状态、已有项目/会话、输入问题、项目归属轻提示、侧栏高亮、AI 回答显示、Bloom 轻量反馈、错误后保留草稿。
- Dashboard 测试应覆盖：项目概览、Bloom 分布、下一步行动、继续提问入口，但不应要求 dashboard 先于提问页出现。
- 路由/导航测试应覆盖：点击“学习提问”直达 ask workspace；点击“学习总览/学生看板”进入 dashboard；点击“层级挑战”进入挑战入口。
- 移动端或响应式测试应覆盖：提问页首屏优先输入和对话，项目/Bloom 辅助区可折叠或下沉。
- 回归测试应防止提问页重新出现大 Hero、三列指标、项目卡片墙或 dashboard 总览作为首屏主体。
- 项目归属相关测试只验证外部行为：提问后展示“已归入《篇目》项目”或等价轻提示，并保持当前对话不中断。
- Bloom 反馈测试只验证学生可见层级提示和攀升建议，不验证内部分类算法细节。
- 挑战测试只验证提问页不会把挑战混入对话主流程，以及 dashboard/项目页能进入独立挑战界面。
- 完成实现前需要运行 lint、TypeScript typecheck、production build，并在浏览器手动验证学生“学习提问”黄金路径。

## Acceptance Criteria

- [ ] 学生导航中“学习提问”进入后首屏就是提问工作区。
- [ ] “学习提问”首屏可见可用输入框，不需要滚动、不需要先点 dashboard 卡片。
- [ ] 提问页首屏不以 Hero、总览指标、项目卡片墙或 dashboard summary 作为主体。
- [ ] 学生总 dashboard 仍存在，用于项目进度、Bloom 分布和下一步行动。
- [ ] Dashboard 与提问页是职责分明的两个表面，而不是 dashboard 包住提问页。
- [ ] 学生自然提问后系统自动归属篇目项目。
- [ ] 项目归属反馈轻量显示，不强制跳转或阻塞确认。
- [ ] 项目/会话上下文辅助提问，但不遮挡输入区。
- [ ] Bloom 层级反馈服务当前对话，不压过提问主流程。
- [ ] 挑战保持独立入口，不混入普通提问页面主流程。
- [ ] 空状态以“提出第一个问题”为主要行动。
- [ ] 错误状态保留学生草稿并允许重试。
- [ ] 移动端首屏仍优先展示输入与对话。
- [ ] 学习总览可提供“继续提问”动作并直达提问工作区。
- [ ] lint 通过。
- [ ] TypeScript typecheck 通过。
- [ ] production build 通过。
- [ ] 浏览器手动验证学生学习提问黄金路径通过。

## Out of Scope

- 不取消学生总 dashboard；本 PRD 只是明确 dashboard 不应成为“学习提问”的前置页。
- 不把整个学生端改成纯 ChatGPT 式单页产品；项目、挑战、画像仍然是必要模块。
- 不把挑战题混入普通提问对话主流程。
- 不重做 Bloom 分类算法或挑战生成算法。
- 不新增复杂游戏化、连续打卡、排行榜或周报系统。
- 不改变教师端学习记录核实闭环。
- 不改变管理员侧学校管理和 AI 运维后台的信息架构。
- 不要求本 PRD 同时实现完整数据模型迁移；如实现发现模型缺口，应另行拆 issue。

## Further Notes

这份 PRD 的底线是：学生点击“学习提问”，就应该立刻进入提问，而不是被产品团队自嗨的看板挡住。Dashboard 当然重要，但 dashboard 的职责是复盘和导航；提问页的职责是让学生把不懂的问题马上问出来。任何把提问页首屏重新做成总览、Hero、指标墙、任务卡片墙的实现，都应视为不符合本 PRD。
